# Vertical Product MVP acceptance

## Automated acceptance

- The offline Vertical Product Host contract runs against the installed Watch Extension and a non-production Fixture Extension.
- The journey covers native Project/Session resume, generic Artifact projection, Asset-to-Chat reference identity, and full native Canvas round-trip context.
- Web tests never call a text or image provider.
- Watch Kernel validation checks the native Design Dialogue options, 3–6-card range, visible `userConstraints`, immutable knowledge evidence, and BaseModel completeness.
- `NativeJarvisApp` imports no Extension; the native workspace remains a separate deletion-safe entry.

## Manual smoke

Environment: local Web/API/Agents services with development authentication bypass and the Watch project.

Verified:

1. Product root opened as **Watch Design Studio**, with native Project `手表` and its persisted Chat session.
2. Chat was the dominant surface; Canvas was hidden by default.
3. Project/Session navigation and Native Asset Center opened without creating parallel records.
4. Professional Workspace opened the complete mounted Jarvis Canvas and returned to the same Product View context.
5. Agents runtime `/skills` discovered `watch-design-kernel` without load errors.
6. A live text-provider turn loaded the Kernel and returned a native pending `ask_user` before Media with three complete strategy cards, exactly `按此策略生成` / `调整策略`, and no digest in user-visible content. No image was requested for this smoke.
7. The native production build passed while `installedExtension.ts` and `watchExtension.ts` were physically removed from the source tree, then the files were restored.

A prior provider-backed Watch generation in this same project verified native Media generation, persisted Canvas output, and immutable `sourceEvidence`. The final directional `ask_user` copy is now Kernel-driven and must still be quality-checked whenever the provider/model configuration changes; it is not part of the offline default gate.

## Known MVP limits

- Brand configuration intentionally contains only the product name, compact mark, and accent color; full visual identity, motion, and responsive polish remain later work.
- Artifact Card enhancement requires stable native asset identity plus a matching Canvas node; otherwise it deliberately falls back to the existing thumbnail.
- Asset Center attaches only media that the existing Chat reference path can consume; text and webpage assets retain their native Asset Center actions.
- Fixture Extension is contract-test-only and is never exposed as a selectable category.
- No runtime plugin marketplace, vertical switcher, Watch database table, Watch Canvas node type, or vertical lifecycle callback is introduced.
