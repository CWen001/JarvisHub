# Storyboard Visual Assets

## Mission

从已经完成的分镜剧本中提取可复用视觉资产，并生成角色定妆图、场景 Base 图与必要的关键道具参考图。

这个 skill 是 `storyboard-script-writer` 的下游，不替代它：

- `storyboard-script-writer`：把剧情/想法写成分镜剧本。
- `storyboard-visual-assets`：从已有分镜剧本生成视觉锚点资产。

默认输出中文。除非用户明确说“只要资产清单/只要 prompt/不要生成图片”，否则目标是**直接产出图片资产**。

## Success Definition

一次合格交付必须满足：

- 不改写剧本、不新增剧情、不重排 Shot。
- 覆盖分镜剧本里持续出现或承担叙事功能的主要角色。
- 覆盖分镜剧本里会复现、承载动作或承担情绪转折的主要场景。
- 只为剧情关键道具生成参考图，不为一次性小物件浪费生成额度。
- 角色图能锁定外观：脸型、发型、年龄感、服装、体态、标志物。
- 场景 Base 图必须是纯环境图：无人、无动物、无角色剪影、无主体道具抢占。
- 道具图必须是单体资产图：干净背景、主体居中、形态和材质清楚。
- 有画布上下文时，必须把图片节点写入画布；不要只返回文字说明。
- 每个生成节点都要有明确标题与资产类型，例如 `角色定妆｜小夏`、`场景Base｜雨夜街头`、`道具参考｜退稿信`。

## Inputs

优先从用户本轮输入或上下文中读取：

- `Basic Info`：题材、比例、时长、风格、语言。
- `Characters`：角色名、身份、外观、情绪变化、生产备注。
- `Fixed Scenes`：场景名、时间地点、空间结构、光线、氛围。
- `Script / Shot 表`：每个镜头里的可见角色、场景、关键道具、动作与情绪。
- `Production Notes / Medium Lock`：统一画风、负面约束、模型建议。
- 已有参考图或画布节点：角色卡、场景图、道具图、分镜图。

若输入不是完整剧本，但包含足够的角色/场景/镜头信息，也可以继续执行。若完全没有分镜剧本或视觉资产来源，应先说明缺少已完成剧本，并让用户提供剧本或先使用 `storyboard-script-writer`。

## Workflow

1. **读取剧本事实**
   - 提取标题、题材、统一风格、画幅比例。
   - 提取 `Characters` 与 `Fixed Scenes`。
   - 扫描 Shot 表，确认每个角色/场景是否真实出现。
   - 记录关键道具：只保留推动剧情、身份识别、转场触发、情绪转折或镜头复用的道具。

2. **建立资产清单**
   - 角色编号：`CH-01`、`CH-02`...
   - 场景编号：`BG-01`、`BG-02`...
   - 道具编号：`PR-01`、`PR-02`...
   - 每个资产写明来源 Shot、视觉职责和是否需要生成。

3. **去重与筛选**
   - 同一角色的不同情绪不拆成多张，除非有年龄变化、伪装形态、战损形态或用户明确要求。
   - 同一地点的不同镜头不拆成多张，除非空间/时间/天气/布景发生本质变化。
   - 道具只生成关键道具；普通背景物只写进场景 prompt。

4. **生成图片**
   - 有画布上下文或用户在画布中工作：使用当前图像生成能力真实提交每张角色/场景/道具图。
   - 每张资产使用稳定输出身份（命名：角色 `character_<slug>_pose_<n:02d>`、场景 Base `scene_base_<slug>`、道具 `prop_<slug>_<n:02d>`），同一输出身份重提应更新原目标，避免重复节点。
   - **fan-out 前 precheck**：先读取真实画布状态。已有稳定节点且 `status=success`、`persisted=true` 的稳定输出身份跳过；`status=error` 或持久化未完成的对**同一输出身份**恢复/重提；仅对完全不存在的稳定输出身份派发新 generate。
   - 若返回 pending，必须继续等待，直到 `status=success`、`persisted=true` 后才能声明该资产已生成。
   - 多资产可先 fan-out 提交全部生成请求，记录每个输出身份、nodeId、任务状态和 label，再逐个收集持久化终态；不在 Agent 上下文维护内部 URL。
   - 不要用结构编辑工具创建 `data.kind="image"` 的可执行媒体节点等待宿主 auto-run；后续普通结构性画布编辑使用窄语义工具。
   - 没有画布上下文时按当前 harness 暴露的图片生成工具执行，不在 skill 内维护公共接口配置。

5. **回报结果**
   - 简短列出已生成/已落画布资产。
   - 若有失败，报告具体资产名、失败原因和下一步可重试范围。
   - 不要把长篇内部 prompt 全量贴给用户，除非用户要求。

## Asset Selection Rules

### 必须生成角色图

为以下角色生成角色定妆图：

- 主角、重要配角、反派、关键关系人物。
- 跨多个 Shot 出现的角色。
- 服装、年龄、外形或道具对识别很重要的角色。
- 虽然只出现一次，但承担剧情转折的角色。

不要为以下对象生成角色图：

- 没有持续叙事功能的路人、群众、背景人影。
- 只在台词里被提到但画面不出现的人。
- Shot 里只是氛围的一次性模糊人群。

### 必须生成场景 Base

为以下场景生成纯环境 Base 图：

- 分镜中复现的地点。
- 角色动作发生的主要空间。
- 氛围转折、剧情转折、视觉风格锚点所在地点。
- 视频或分镜后续要反复引用的空间。

场景 Base 图禁止：

- 出现角色、动物、人物剪影。
- 把关键道具画成主体，除非这个道具是场景固定结构的一部分。
- 出现不可控大段文字、招牌乱码或剧本文字。

### 可选生成道具图

只为以下道具生成独立参考图：

- 信件、钥匙、武器、手机、合同、日记、地图、徽章、药瓶等剧情触发物。
- 角色身份识别物或反复出现的标志物。
- 后续镜头需要保持形态一致的物品。

不要为普通家具、路灯、雨伞、桌椅等背景元素单独生成，除非剧本明确让它承担剧情功能。

## Prompt Construction

### 角色定妆图 Prompt 必含

- 资产编号与角色名。
- 年龄、性别表达、体态、脸型、发型、服装、标志物。
- 角色气质和默认表情。
- 统一项目风格、画幅比例、材质、光线。
- 干净背景或简洁角色卡布局。
- 负面约束：不要多人物、不要换服装、不要文字乱码、不要夸张变形。

推荐标题：

```text
角色定妆｜CH-01 小夏
```

### 场景 Base Prompt 必含

- 资产编号与场景名。
- 空间结构、入口/出口、固定物、光线方向、天气、时间段。
- 色彩气氛与叙事功能。
- 明确要求“纯环境、无人、无动物、无角色剪影”。
- 避免大段文字，招牌/标识如非必要只画成简化符号。

推荐标题：

```text
场景Base｜BG-01 雨夜街头
```

### 道具参考 Prompt 必含

- 资产编号与道具名。
- 外形、材质、尺寸感、磨损、颜色、可读标识。
- 干净暗底或中性底，单体居中。
- 无人物、无手、无复杂场景。

推荐标题：

```text
道具参考｜PR-01 退稿信
```

## Canvas Execution Rules

当上下文里有真实画布 scope 时：

- 生成图片节点优先使用当前图像生成工具；若任何节点返回 pending，必须对对应输出身份或任务继续等待。多资产可先全部提交，再逐个收集结果；禁止只提交 queued/running 节点后汇报“资产图已生成”。
- 每个生成请求必须具备这些语义，不在本 skill 维护字段清单：
  - 图片任务类型和稳定节点身份
  - 清晰 label
  - 最终执行 prompt
  - 画幅 / 尺寸意图
  - 角色、场景、道具或连续性锚点说明
- 资产职责写入 label / prompt / 生产清单；不要新增未暴露字段。
- 锚点或参考绑定只在当前 harness canvas tool schema 明确支持时使用；如果 schema 不支持，不要伪造字段。
- 若已有权威参考图，使用当前 schema 支持的参考图输入，不要只在 prompt 里口头提到。
- 不要创建视频节点。
- 不要创建 `storyboard` 编辑器节点。

节点布局建议：

- 第一列：角色图，从上到下。
- 第二列：场景 Base 图，从上到下。
- 第三列：关键道具图，从上到下。
- 间距保持可读，不要把所有节点堆叠到同一位置。

## Output When Not Executing

只有用户明确要求“不生成图片 / 只要清单 / 只要 prompt”时，输出这个结构：

```markdown
## 视觉资产清单

### 角色
| ID | 名称 | 来源 Shot | 生成策略 | Prompt 摘要 |
|---|---|---|---|---|

### 场景
| ID | 名称 | 来源 Shot | 生成策略 | Prompt 摘要 |
|---|---|---|---|---|

### 关键道具
| ID | 名称 | 来源 Shot | 生成策略 | Prompt 摘要 |
|---|---|---|---|---|
```

## Failure Policy

明确失败，不做假交付：

- 没有分镜剧本或可解析的角色/场景信息：要求用户提供剧本，或建议先使用 `storyboard-script-writer`。
- 缺少画布 scope 但用户要求“放到画布”：请求用户打开/提供目标画布。
- 图片生成失败：报告失败资产，不要伪造成功状态，不要改用别的模型静默重试。
- 参考图缺失：如果不是硬依赖，可以按文本生成；如果用户要求保持某张画布参考图一致但没有稳定节点 ID 或尚未持久化完成，必须显式失败。非画布外部参考仍可使用 URL-only 引用。

## Anti-Patterns

禁止：

- 重新写一份分镜剧本。
- 只输出大段 prompt，不生成资产。
- 给每个 Shot 都生成一张图；那是分镜图任务，不是视觉资产任务。
- 把场景 Base 画成人物剧情画面。
- 把角色图画成剧情截图。
- 为无关路人或普通背景物生成大量资产。
- 用“高清、电影感”这类空泛词替代具体外观、空间和材质。
- 忽略用户剧本里的硬设定，自行改角色年龄、服装、地点或时间。

## Completion Criteria

输出前必须满足：

1. 是否保持原剧本不变。
2. 是否覆盖主要角色。
3. 是否覆盖主要场景。
4. 是否只选择关键道具。
5. 场景 Base 是否明确无人、无动物、无角色剪影。
6. 每个资产节点是否有明确 label、prompt、资产职责。
7. 有画布上下文时，是否已经写画布或提交生成，而不是只给文字。
